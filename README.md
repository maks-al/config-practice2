# Практическая работа №2 - вариант 1, этап 1

Консольная программа на Python для настройки анализатора зависимостей NuGet.
На первом этапе она читает шесть параметров из CSV, проверяет их и
выводит в формате `ключ: значение`.

## Требования

- Windows, Python 3.10 или новее

## Запуск

Открыть PowerShell в папке проекта и выполнить:

```powershell
py run.py
py run.py --config examples/config_nuget.csv
```

При запуске без параметров используется `examples/config_test.csv`.

Пример вывода:

```text
package: A
repository: test_repo.txt
test_mode: true
version: 1.0.0
max_depth: 3
filter:
```

## Формат CSV

Два столбца: `key,value`. Обязательные параметры:

| Ключ | Значение |
|---|---|
| `package` | Имя NuGet-пакета или имя тестового узла (`A`, `B`...) |
| `repository` | HTTP(S) URL или путь к тестовому файлу |
| `test_mode` | `true` либо `false` |
| `version` | Версия, например `13.0.3` |
| `max_depth` | Неотрицательное целое число |
| `filter` | Подстрока фильтра; может быть пустой |

В тестовом режиме путь `repository` считается относительно CSV-файла
Пример файла тестового репозитория: `examples/test_repo.txt`
На этом этапе проверяется существование файла, граф ещё не анализируется

## Проверки

```powershell
py -m unittest discover -s tests -v
py tests/scenarios.py
```

Вторая команда показывает в консоли выполняемые команды, вывод и ошибки

## Основные функции

| Функция | Назначение |
|---|---|
| `read_rows()` | Считывает ключи и значения CSV |
| `check_mode()` | Проверяет `true/false` |
| `check_package()` | Проверяет имя пакета |
| `check_repository()` | Проверяет URL или путь к файлу |
| `check_version()` | Проверяет версию |
| `check_depth()` | Проверяет глубину |
| `check_filter()` | Проверяет фильтр |
| `load_config()` | Собирает проверенную конфигурацию |
| `main()` | Запускает CLI и выводит настройки |

## Файлы

- `run.py` - точка входа
- `src/main.py` - параметры CLI и вывод
- `src/config.py` - чтение CSV и тесты
- `examples/` - 2 примера конфигурации и тестовый файл
- `tests/` - автоматические тесты
- `Makefile` - дополнительный способ запуска, если установлен `make`
